# Desktop 可靠性修复设计

沿用已批准的候选设计，基线 2920a3b。以逐文件哈希核对和 apply_patch 合入 59 文件候选，保留独立模块与原配置/API兼容。

补充设计：

1. taskAdmissionService 在单进程后端同步预留 Job 创建资格，覆盖 createJob 的全部异步持久化，finally 释放。
2. 安装下载完成后先关闭准入，再读取活动 Job；有 Job 或读取失败则恢复准入。安装辅助进程启动失败也恢复，成功后保持关闭直到退出。下载期间不锁定用户操作。
3. commandState 作为可测试的纯函数，将命令发出记录、端口状态和运行归属分开；面板分别提供启动与停止按钮。
4. 命令停止必须执行用户保存的命令，只有成功退出且配置端口关闭后才确认；不会自动重试或强杀未验证的进程树。
5. 配置锁错误附带路径与恢复文档，明确要求先保留草稿、核验写入进程，不能盲删。
6. Jest 只运行 backend 套件，Node 测试单独运行 frontend 和 reliability，并全部接入 CI。
7. 浏览器验收使用独立静态构建与合成 API/WS，无真实配置、数据库和 shell 操作。

不扩展为多实例/分布式维护锁，不迁移历史数据库，不实现长期守护或完整断电事务恢复。
