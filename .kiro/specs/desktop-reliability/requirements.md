# Desktop 可靠性修复需求

用户已审阅候选报告并要求直接修改。范围为当前 desktop 控制台，不修改 sibling metersphere，不启动/重启已安装 App，不提交或发布。

- 当多个入口编辑配置时，不得静默覆盖其他入口的修改；保存响应不能清除后续草稿。
- 当端口归属不明确时，不得据此接管/终止无关进程。
- 当普通项目没有探测端口时，显示运行状态未验证；启动和停止都可操作。
- 当用户请求停止普通项目时，即使端口未监听，也执行保存的停止命令。
- 安装切换阶段必须与新 Job 创建互斥，并覆盖正在持久化但尚不可查询的 Job；失败后恢复任务准入。
- 保持单窗口导航、SQL 草稿、原 API 和事件兼容；不恢复应用快捷键。
- SQL 查询应可取消、有返回数据上限，且新查询不能沿用旧结果的成功提示。
- 遗留配置锁保守拒绝覆盖，提供路径和恢复指引；不自动猜测后删除。

真实业务进程/MySQL/签名安装回滚仍需专项验收，不以替身测试代替。
