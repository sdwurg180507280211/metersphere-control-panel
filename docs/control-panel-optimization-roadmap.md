# Control Panel 优化路线图

## 概述

`control-panel` 用于辅助启动同级目录下的 `metersphere` 多服务项目，核心职责包括：

- 启停 Java 后端服务
- 构建并发布多个前端模块
- 展示实时日志与构建进度
- 作为本地开发辅助控制台，降低多模块联调成本

当前项目已经具备可用的控制面板能力，但在“进程控制、构建链路、状态同步、日志性能、仓库卫生”几个方向仍有继续优化空间。

## 任务

### 优先级高

- [x] 1. 进程管理升级为可控进程模型
  - [x] 1.1 服务启动改为真实子进程 `spawn`，不再依赖 shell 包装
  - [x] 1.2 停止与状态检测已接入 PID、端口与 `pgrep` 兜底
  - [x] 1.3 批量操作已收敛为统一编排入口
  - [x] 1.4 批量启动失败时自动回滚本次已启动服务
  - [x] 1.5 已补充批量重启能力，统一启动/停止/重启编排
  - **收益**：降低误杀与漏杀概率，提高“启动/停止/重启”结果的可预测性。

- [x] 2. 构建取消做成真正可中断
  - **问题**：如果 UI 只改状态、不终止真实 `npm` 子进程，会导致页面状态与后台执行状态漂移。
  - **已完成**：构建进程已建立独立跟踪；取消构建会主动终止对应进程；`cancelled` 状态会保留并写入构建历史。
  - **收益**：构建状态更可信，避免残留构建任务继续占用 CPU / IO。

- [x] 3. 构建默认跳过重复安装依赖
  - [x] 3.1 构建前检测本地依赖目录，存在时跳过重复安装
  - [x] 3.2 需要安装依赖时优先使用 `npm ci`
  - [x] 3.3 基于 lockfile 指纹决定是否重新安装依赖
  - **收益**：显著减少重复构建耗时，降低网络与包管理器状态对本地开发的影响。

- [x] 4. 配置源收敛为单一元数据来源
  - [x] 4.1 以后端配置为单一来源统一生成服务目录
  - [x] 4.2 以后端配置为单一来源统一生成前端构建模块目录
  - [x] 4.3 后端校验映射改为复用统一元数据而非多处硬编码
  - [x] 4.4 前端通过 API 动态拉取服务与模块列表
  - **收益**：新增或调整模块时只需要改一个地方，避免前后端配置不一致。

### 优先级中

- [x] 5. 批量启动改为“按健康状态推进”
  - [x] 5.1 启动单个服务后轮询端口或健康接口
  - [x] 5.2 确认服务健康后再启动下一个依赖服务
  - [x] 5.3 对超时、失败、半启动状态输出明确提示，并中止后续启动
  - [x] 5.4 Checkpoint - 批量启动稳定性优化完成
    - 启动全部时已不再固定 sleep 推进，而是按健康状态逐个放行
    - 当前批量启动在依赖服务未就绪时会停止继续启动后续服务
  - **收益**：提高整套服务启动成功率，减少批量启动后部分服务挂掉的情况。

- [x] 6. 日志链路性能优化
  - [x] 6.1 `build` 与 `service` 日志筛选状态已拆开，避免筛选条件互相串扰
  - [x] 6.2 前端日志存储已改为日志行数组 / ring buffer 风格增量追加
  - [x] 6.3 搜索与过滤基于日志行处理，避免对整段日志反复 `split/join`
  - [x] 6.4 长日志列表已接入虚拟滚动，降低大日志量下的渲染压力
  - [x] 6.5 服务端日志写盘已切换到 `createWriteStream`
  - **收益**：降低内存抖动和主线程阻塞，提升高日志吞吐场景下的 UI 流畅度。

- [x] 7. 充分利用 WebSocket，减少轮询
  - [x] 7.1 构建取消已改为调用 `/api/progress/:buildId/cancel`，结果通过 WebSocket 回推
  - [x] 7.2 已修复 `useCancelBuild` 额外创建 WebSocket 连接的问题
  - [x] 7.3 服务状态变化已支持 WebSocket 增量推送
  - [x] 7.4 前端轮询仅在连接失败或断线恢复时保留兜底
  - [x] 7.5 Checkpoint - 服务状态同步机制切换
    - [x] 服务状态变更已通过 WebSocket 增量推送
    - [x] 前端仅在断线恢复场景保留轮询兜底
  - **收益**：页面状态更实时，减少无意义请求与状态抖动。

- [x] 8. 日志筛选状态按类型隔离
  - **问题**：构建日志和服务日志共用筛选条件时，切换页面体验会互相影响。
  - **已完成**：已按日志类型分别存储 `logLevel` 与 `searchTerm`。
  - **收益**：减少切换 Tab 时的认知干扰。

### 优先级低但值得做

- [x] 9. 构建产物复制改用 Node 原生文件 API
  - **问题**：基于 `rm -rf`、`cp` 的复制方案依赖 shell，路径处理和平台兼容性较弱。
  - **已完成**：已完成第一阶段替换，改用 Node 原生文件 API 处理构建产物复制。
  - **收益**：路径更安全，可维护性更好，降低 shell 命令拼接风险。

- [x] 10. 健康检查并行化
  - [x] 10.1 批量健康检查改为 `Promise.allSettled` 并行探测
  - [x] 10.2 优先解析 actuator 返回内容，而不是只判断 HTTP 200
  - [x] 10.3 Checkpoint - 健康检查能力增强完成
    - 健康检查结果可识别响应体中的 `status: UP`
    - 批量探测不再串行阻塞整体结果返回
  - **收益**：更快得到全量服务健康状态，健康信息也更准确。

- [x] 11. 开发/生产职责与文档对齐
  - [x] 11.1 已更新 `README` 中的实时日志与状态同步描述
  - [x] 11.2 已明确记录 WebSocket 为当前主通道，并保留 SSE 兼容说明
  - [x] 11.3 已明确开发模式与生产模式的静态资源职责边界
  - [x] 11.4 已补充接口与运行机制说明
  - [x] 11.5 Checkpoint - 文档与实现一致性验证
    - [x] 文档描述与当前实现保持一致
    - [x] 新维护者可按文档完成本地启动与问题排查
  - **收益**：降低维护者误解，提升项目上手效率。

- [x] 12. 仓库卫生治理
  - **问题**：本地运行会生成 `logs`、`.pids`、`frontend/dist` 等产物，如果未忽略会污染工作区和提交记录。
  - **已完成**：已补充 `.gitignore`，忽略常见运行时产物。
  - **收益**：让提交更聚焦，降低误提交概率。

- [x] 13. Redis 降级策略简化
  - [x] 13.1 默认以内存缓存为主，Redis 仅在显式配置时启用
  - [x] 13.2 已去掉默认敏感密码，改为环境变量或 MeterSphere 配置注入
  - [x] 13.3 Redis 连接失败时自动降级回内存缓存
  - **收益**：降低本地运行门槛，提高安全性与可移植性。

## 已完成阶段

- [x] 阶段一：进程与构建控制主链路重构完成
  - 服务启动改为直接拉起真实子进程
  - 停止与状态检测接入 PID、`pgrep` 与端口兜底
  - 构建取消支持真实终止，`cancelled` 状态与历史记录保持一致
  - 默认跳过重复 `npm install`

- [x] 阶段二：配置源与前端状态同步第一轮收敛完成
  - 服务目录与前端模块目录改为由后端统一生成
  - 前端动态拉取服务与模块列表，不再维护本地常量
  - 构建取消改走统一进度取消接口，状态由 WebSocket 回推
  - `useCancelBuild` 额外 WebSocket 连接问题已修复

- [x] 阶段三：体验与仓库卫生修复完成
  - 日志筛选状态按 `build/service` 维度拆开保存
  - `.gitignore` 已补充本地产物与运行痕迹忽略规则

- [x] 阶段四：批量启动稳定性优化完成
  - 启动全部改为按健康检查顺序推进，而不是固定等待几秒
  - 依赖服务未通过健康检查时会中止后续启动并返回明确结果

- [x] 阶段五：服务状态实时同步完成
  - 服务启停与异常退出已通过 WebSocket 增量推送状态
  - 前端收到状态事件后可直接刷新对应服务按钮状态
  - 服务页仅在 WebSocket 断线时保留轮询兜底，并在重连后自动全量同步

- [x] 阶段六：日志链路性能优化完成
  - 前端日志改为按行缓冲存储，并保留未完成尾行用于下一次增量拼接
  - 搜索与筛选改为基于日志行处理，减少高频字符串重建
  - 长日志列表接入虚拟滚动，降低大日志量下的 DOM 渲染压力
  - 服务端日志写盘切换到 `createWriteStream`，降低事件循环阻塞

- [x] 阶段七：构建依赖安装策略优化完成
  - 构建会记录 lockfile 指纹，并在依赖未变化时跳过重复安装
  - 当 lockfile 变化或用户强制安装时，仍会自动执行依赖安装

- [x] 阶段八：进程批量编排与失败恢复优化完成
  - 批量启动 / 停止 / 重启已收敛为统一后端编排链路
  - 批量启动遇到健康检查失败时，会回滚本次已启动的服务

- [x] 阶段九：缓存层降级策略优化完成
  - 默认使用内存缓存，Redis 改为显式启用的可选增强
  - 默认敏感信息已移除，Redis 连接失败时会自动回退到内存缓存

- [x] 阶段十：文档与运行职责对齐完成
  - `README` 已更新为 WebSocket 主通道、SSE 兼容的当前实现描述
  - 开发 / 生产职责、接口说明、缓存模式与运行方式已统一对齐
