# 康弘会议管理系统项目一页式汇报

基于近 17 次项目沟通会整理

## 一、项目现状

项目已经完成从“需求发散讨论”向“规则收口与开发落地准备”阶段的切换。

目前四大核心板块已经基本明确：

- 医生/讲者系统
- 会议申请系统
- 会议执行系统
- 会议结算系统

项目整体主链路已经清晰：

`HCP入库 -> 升级讲者 -> 讲者审核/评级 -> 会议申请 -> 审批 -> 会议执行 -> 材料归档/核验 -> 结算支付`

当前判断：

- 项目方向清楚
- 功能主框架清楚
- 真正影响推进速度的，不再是页面功能本身，而是财务、合规、审批和验收规则

## 二、已经明确的关键结论

### 1. 范围与策略

- 一期范围聚焦四大板块，不再无限扩展
- 一期采取“先形成可运行闭环，再做复杂增强”的策略
- 需求范围以 `URS` 和合同边界为准，超出部分原则上放二期

### 2. 技术与部署

- 系统确定采用`本地化部署`
- 核心主数据字段尽量标准化、字典化、下拉化

### 3. 核心流程

- 讲者准入必须经过四要素验证和第三方评级
- 评级不一致时设置申诉期，且申诉只能由经理发起
- 会议变更只要影响费用，就必须重走流程
- 结算明确拆为`劳务确认`和`报销结算`两步
- 非检一期只做基础能力，不做完整闭环

## 三、当前最关键的未定事项

以下事项是当前最影响项目推进的卡点：

1. 财务审批流最终口径
包括预算字段由谁填写、在哪一步填写、结算最终如何审核。

2. 编号规则统一方案
包括会议编号、流程编号、结算单号、讲者/HCP 编号、材料编号。

3. 合规口径确认
包括线上签到、纸质签到表、归档材料、法务文本。

4. 合同与验收条款
如果验收标准与当前方案不一致，后续将有较大交付风险。

5. 第三方能力边界与时效
尤其是讲者评级返回时效、电子签稳定性、异常处理方式。

## 四、项目主要风险

### R1. 财务流程风险

财务审批链和费用分摊逻辑如果继续变化，会导致开发和 UI 反复返工。

### R2. 合规风险

签到、纸质材料、电子签、非检边界如果没有正式口径，上线后仍可能被推翻。

### R3. 范围膨胀风险

如果没有明确的一期/二期边界，项目容易持续被追加需求。

### R4. 验收风险

合同和验收条款若未和当前方案一致，后期可能出现“系统已做，但验收不过”的问题。

### R5. 第三方依赖风险

讲者评级、四要素验证、电子签等都依赖第三方，一旦 SLA 不稳，核心流程就会被卡住。

## 五、建议立即推进的 5 项动作

1. 尽快组织一次`财务定口会`
目标：一次确认预算字段责任、审批链、结算口径。

2. 输出`编号规则清单`
目标：避免系统内部各模块各自生成规则，后期返工。

3. 与法务/合规完成一次`材料口径确认`
目标：明确签到、归档、纸质材料和知情同意文本。

4. 输出`一期/二期边界清单`
目标：保护当前排期，减少需求膨胀。

5. 固化`里程碑计划`
目标：明确 UI 定稿、开发、联调、培训、试运行、上线时间。

## 六、总体判断

项目现在不是“方向不清”，而是“规则待定”。

如果接下来能尽快定下以下四组问题：

- 财务流程
- 合规口径
- 编号规则
- 验收边界

那么项目就可以比较顺畅地进入开发、联调和试运行。

如果这四类问题继续悬而不决，那么项目表面上会继续推进，但本质上仍会停留在反复返工和持续确认阶段。
