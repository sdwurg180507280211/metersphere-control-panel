# Desktop 可靠性改进与本机验证

## 交付状态与范围

本变更集基于 `desktop@2920a3bc397b7766fb7ffc8aad3d5a9c26ccf154`。已将 59 文件候选合入本地工作区并补充修复，不是已推送、已发布或已完成真实业务桌面验收的版本。配套 `metersphere` 仓库不在修改范围。

保留现有 Electron、Express、React、Zustand、单窗口导航、配置字段和旧事件兼容入口。改动集中于此前审查指出的进程归属、鉴权、配置一致性、任务观察、失败恢复、资源边界及行为回归测试。

## 主要行为

### 进程与健康

- 将端口监听与受管理进程身份分开；发现端口并不直接获得终止权限。
- 恢复、接管、停止前检查进程身份，包括启动标识、工作目录、POM 参数和项目路径；无法核验时保守拒绝接管或终止。
- Linux 使用 `/proc`，macOS 使用系统进程和工作目录信息。已在本机验证真实临时 Node 子进程的身份读取；真实 MeterSphere/Maven 启停仍需验收。Windows 不属于正式支持范围。
- Actuator HTTP 探测要求有效 JSON 且 `status: UP`，限制响应体大小并处理超时、取消和中断。原先以 HTML 200 作为健康结果的自定义端点不再视为 Actuator 就绪。
- 前端保留进程存活、健康、归属等附加字段，不再在状态归一化时丢弃这些信息；明确传入空健康结果会清除旧值。

### 请求与连接

- HTTP 写操作与浏览器 WebSocket 握手采用精确允许来源，开发模式单独允许 Vite 来源。
- 无 Origin 的 WebSocket 请求必须带令牌；本机 HTTP CLI 兼容模式保留，`MS_REQUIRE_LOCAL_TOKEN=1` 可要求本机请求也带令牌。
- WebSocket 增加消息和客户端数量限制、心跳销毁、发送积压控制。日志积压会报告缺口；不能可靠送达控制事件时断开慢客户端，由客户端重新同步。
- 客户端采用退避重连、连接代次隔离、手动重连和网络恢复触发，不再以刷新整个应用作为唯一恢复方式。

### 配置与草稿

- 配置写入统一使用私有文件、原子替换、备份、写入锁和版本校验；损坏 JSON 拒绝静默覆盖。
- 常规配置保存只合并其拥有的字段，项目元数据由对应写入口维护；比较有效配置时考虑默认值归一化。
- 前端提交它实际编辑的配置版本；诊断刷新不会偷偷推进草稿的基线版本。
- 保存进行中继续输入的草稿不会被较早请求的成功响应清空。
- 崩溃留下的写入锁需要核验进程后人工恢复，不自动猜测或删除正在使用的锁。

### 启动、关闭与更新

- HTTP 监听与异步初始化分开传播错误；初始化失败和超时能结束启动等待并进入有界清理。
- `/api/health` 表示 HTTP 存活，`/api/ready` 表示初始化就绪。
- 关闭时清理控制台自己的观察器、连接池、WebSocket 和日志资源；保留业务服务的默认规则不变。
- 更新下载检查文件名、来源、哈希及下载大小；安装辅助脚本保留上一版本，直到新版本以版本、随机标识和进程身份确认后端及界面就绪。
- 更新辅助脚本已在本机使用临时应用目录和命令替身测试，不能替代 macOS 签名、安装权限与真实 App 回滚验收。
- 安装前先同步关闭 Job 准入，再检查所有活动 Job；Job 创建从进入到持久化完成均有预留保护。检查/辅助进程启动失败会恢复准入，成功后保持关闭直至退出。下载期间不锁定操作。这是单进程后端的 Job 准入保护，不是多实例分布式维护模式；未接入 Job 的独立操作不能据此宣称获得同样保护。

### 构建与工具链

- 构建产物先复制到暂存目录、校验后切换；复制或切换失败时保留恢复来源。路径越界、符号链接等危险目标受到检查。
- 发布事务保留恢复记录；本次未实现所有断电/崩溃场景的自动恢复，不能把记录存在等同于自动修复完成。
- 依赖指纹涵盖 manifest、锁文件、npm 配置、安装参数与实际外部 Node/npm 版本；工具探测使用缓存。
- Node 安装扫描改为有超时、并发限制与缓存的异步操作。实际耗时和内存收益未做性能基准，不能承诺固定提升比例。
- 不把 Electron 自身的可执行文件当作 MeterSphere 构建用 Node。

### SQL 与命令项目

- SQL 继续依赖独立只读数据库账号，不分析关键词决定权限、不改写用户 SQL。
- 查询采用专用连接和有界流式收集，限制返回行数及 8 MiB 结果数据量；取消、超时与达到上限时清理连接。
- `rowCount` 表示本次返回行数；`rowCountExact: false` 表示没有统计完整结果总数。界面对应显示“总行数未知”。其他 API 使用方需要验收此语义变化。
- 这个上限不是严格的进程 RSS 上限；数据库驱动仍可能先解码一个很大的单行或字段。
- 查询页支持取消、阻止重复执行，浏览器历史保存失败不再把成功查询显示为网络失败。
- 普通命令项目接入 Job 和按项目互斥，观察启动/停止结果并保存私有命令日志。没有状态端口时明确表示未知，不将“命令已发出”等同于服务就绪。
- 前端状态也明确标记“运行状态未验证”；记住的启动操作只是收据。启动/停止按钮独立，端口未监听仍会执行停止命令，以支持清理 worker、容器等其他资源。
- 新查询清除旧结果，避免取消/失败后仍将上次结果标为本次成功；切换项目保留 SQL 草稿。
- 端口探测本身不是命令项目的进程归属证明；观察期后的守护进程退出追踪、命令日志磁盘轮转尚未完成。

## 数据边界

控制台启动默认不主动对 MeterSphere 的打包历史表建表/迁移；设置 `MS_PACKAGE_HISTORY_AUTO_INIT=1` 可恢复启动初始化。

这不是存储迁移：现有按需历史功能及其数据库访问仍保留。没有迁移已有历史、没有删除业务数据库中的表，也没有完成统一的本地持久化任务历史。

## 配置锁恢复

若保存持续提示“配置正在被其他进程写入”：

1. 先保留未保存草稿，短暂等待后重试；正常保存会自动释放锁。
2. 错误响应的 `details.lockFile` 给出实际锁路径（默认为用户配置路径追加 `.lock`），不要猜测路径或删除 config.json/.bak。
3. 只读查看锁中的 pid、createdAt，核验对应进程的身份和启动时间；仅凭 PID 存在/不存在不足以判断是否另有写入者。
4. 确认所有可能写该配置的控制台实例已退出，且没有保存操作后，将确认为遗留的锁移到带时间戳的备份文件，再启动控制台重试。不能确认则保留现场，不执行强杀或删除。
5. 遗留锁不代表配置损坏；不要自动用 .bak 覆盖当前配置。本轮没有提供自动清锁功能。

浏览器隔离验收可在完成构建后运行 `node scripts/tests/reliability-ui-fixture.cjs`。它绑定随机 loopback 端口，只提供合成 API，不加载真实后端配置、不执行命令、不连接数据库。结束后关闭该测试进程。

本地候选的测试日志、源码基线哈希和语法验证结果由随附交付报告记录。语法解析不是类型检查、前端构建、GitHub CI 或桌面验收。
