# 配置管理系统：从“显式定义”到“智能推导” (最终修订版)

经过深度审计，结论非常明确：**目前的 80% 配置项属于“配置债”**。我们应通过系统智能推导与约定优于配置（CoC）原则，将配置体验从“手动填表”进化为“一键探测 + 局部微调”。

---

## 1. 核心技术方案：如何实现“去冗余”？

### 1.1 微服务的精准识别（防误判）
*   **特征检测**：在发现 `pom.xml` 后，检查其内容是否包含 `spring-boot-maven-plugin` 或 `spring-cloud-starter` 等启动类插件。
*   **资源校验**：核实 `src/main/resources` 下是否存在 `application.yml` 或 `application.properties`。
*   **结果**：仅将真正的“微服务入口”呈献给用户，彻底消灭 `services` 配置冗余。

### 1.2 端口与健康检查的解析策略
*   **轻量化解析**：
    *   **YAML**: 使用 `js-yaml` 库解析标准配置文件。
    *   **Properties**: 优先使用**极简正则匹配**（如 `/^server\.port\s*=\s*(\d+)/m`）来提取端口，以追求最高执行效率和最小依赖。
*   **路径推断**：默认健康检查路径为 `/actuator/health`。仅在检测到 Eureka 模块时，自动适配其特定路径。
*   **容错处理**：如果 10 个服务中有 1 个因为非标配置解析失败，系统**不应报错**，而是在预览清单中标记该服务为“待补充”，允许用户手动微调。

### 1.3 扫描性能与缓存机制
*   **UI 反馈**：扫描过程提供友好的 Loading 动画，明确告知用户正在“智能探测中...”。
*   **结果缓存**：将扫描到的结果持久化在 `config.json` 的 `resolved` 字段或单独的缓存文件中。
*   **按需刷新**：下次进入配置页时默认加载缓存结果，并提供“重新扫描”按钮，避免每次进入页面都触发高昂的磁盘 IO。

---

## 2. 交互模型：智能但不“失控”

我们采用 **“探测 -> 预览 -> 确认”** 的三步走策略：

1.  **输入锚点**：用户仅需输入 `projectRoot`。
2.  **一键扫描**：点击扫描后，系统执行“魔法”探测逻辑。
3.  **局部微调 (Override)**：展示清单，允许用户对个别“非标”服务进行手动覆盖（如修改端口或关闭特定服务）。
4.  **保存应用**：点击保存，系统仅记录“核心锚点”和“覆盖项”，保持配置文件极其精简。

## 3. 落地节奏（分步实施）

### 阶段 1：底层环境与路径推导 (Quick Win)
*   **后端**：重构配置保存逻辑。若 `npmPath`, `maxJobs` 等缺失，自动通过系统命令补全。
*   **收益**：初步解决跨设备协作时绝对路径冲突的问题。

### 阶段 2：服务智能扫描引擎 (Core)
*   **后端**：开发 `projectScannerService.js`，实现微服务精准识别、高效端口解析逻辑及扫描结果缓存机制。
*   **接口**：新增 `/api/config/scan` 接口，返回探测到的全量信息。

### 阶段 3：前端大重构——“统一设置中心” (UX)
*   **布局**：废弃 8 个弹窗，开发全新的左侧导航布局。
*   **体验**：实现“输入路径 -> 动画扫描 -> 预览清单 -> 局部微调 -> 一键应用”的完整链路。
*   **高级选项**：将 `maxLogLines`, `parallelBuild` 等低频项隐藏至高级折叠面板。

## 4. 桌面端 (DMG/App) 打包适配方案

如果未来将此系统通过 Electron/Tauri 打包为桌面应用，需提前防范以下“环境差异”坑位以保证扫描引擎的高效运转：

1.  **进程环境变量劫持 (PATH)**：打包后，双击启动的自带 UI 进程无法自动加载用户的 `~/.zshrc` 或 `~/.bash_profile`，导致 `which npm` 或 `mvn` 失败。
    *   **解法**：在后端主进程入口注入 `fix-path` 库接管终端环境，或允许用户在基础设置中手动初始化一次绝对路径。
2.  **配置文件读写的沙箱隔离**：打包生成的 `.app` 内部（如 `Contents/Resources`）属于系统级只读目录，写入 `.bak` 会抛错。
    *   **解法**：修改 `ConfigManager` 的寻址逻辑，将 `config.json` 和所有的缓存文件统一定向到用户的专属数据目录（如 `os.homedir() + '/.metersphere-control-panel/'`）。
3.  **系统级权限申请 (TCC)**：当用户选择跨盘符或保护目录（如 Desktop/Downloads）进行扫描时，会触发 macOS 强检。
    *   **解法**：确保文件树遍历方法有严谨的 `try...catch` 块捕获 `EACCES` 等无权限错误，并将明确的授权指引返回给前端界面。

---
**最终目标**：让 `config.json` 回归到只有 3-5 行核心代码，将“配置工作”变为“确认工作”。
