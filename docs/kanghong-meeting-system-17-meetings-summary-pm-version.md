# 康弘会议管理系统近 17 次会议整理

项目经理版本

说明：

- 本文基于 2026-01-29 至 2026-03-10 的 17 次会议转写稿整理。
- 与普通会议纪要不同，本文重点输出：`明确决策`、`决策原因`、`项目影响`、`下一步待办`、`主要风险`。
- 适合用于项目周报、阶段汇报、内部对齐和后续会议跟踪。

---

## 一、项目阶段判断

### 1. 当前所处阶段

项目当前处于`需求收敛完成、UI/流程基本成形、关键审批与合规规则待最后拍板`的阶段。

换句话说，项目不是“还在纯需求讨论”，也不是“已经完全进入开发稳定推进”，而是处在一个典型的`从方案确认进入开发落地前的收口阶段`。

### 2. 当前阶段的三个核心特征

- 主业务流程已经基本搭起来了，尤其是讲者准入、会议申请、会议执行、会议结算四大主链路已经有了清晰框架。
- 真正阻碍项目快速进入稳定开发的，不再是“有没有功能”，而是`审批链条、财务规则、合规口径、权限边界`这些规则性问题。
- 客户对系统的期待不只是“能用”，而是要能支撑合规审查、纸质归档、真实留痕、本地化部署和后续审计。

### 3. 当前项目总判断

项目方向是清晰的，范围边界也比前期更明确，但若以下事项不能尽快拍板，仍会持续拖慢开发和联调：

- 财务审批流最终口径
- 预算字段与成本中心填报责任
- 编号规则统一
- 签到/纸质材料的合规口径
- 非检一期边界
- 合同与验收标准

---

## 二、项目级核心结论

### 1. 已经基本明确的项目级结论

- 一期建设范围明确围绕四大板块推进，不再无限扩展。
- 一期交付策略明确是“先形成可运行闭环，再做复杂增强”。
- 本地化部署已经不是备选项，而是确定前提。
- 项目真正的高风险点集中在`流程规则`而不是页面展示。
- 客户最关注的，不只是业务流转效率，而是`真实性、留痕、可审计、可归档`。

### 2. 当前最值得项目经理重点盯住的六类事项

- 范围是否继续膨胀
- 财务与合规规则是否及时给出正式口径
- 第三方能力是否与系统规则一致
- 一期功能与二期功能的边界是否持续被打破
- 培训、试运行、上线是否被动后移
- 合同和验收标准是否与当前方案一致

| D-32 | 非检需要独立后台账号/入口，不依赖 HCP 或讲者端身份体系。 | 外部非检人员不适合走公众号身份体系。 | 影响权限模型、账号发放和后台菜单。 | 设计非检账号权限最小集。 | 如果权限隔离不严，可能暴露不该看的会议信息。 |

| P-10 | 历史会议展示和归档保留时长 | 会议中有多个时间口径，尚未统一。 | 列表展示、历史查询、归档检索逻辑会受影响。 | 产品经理、客户业务方 | 中 |
| P-11 | 合同与验收条款最终确认 | 合同特别是验收条款有较多改动，尚需细看。 | 可能出现“方案这么做了，但验收按另一套标准卡人”的风险。 | 商务负责人、项目经理、法务 | 最高 |
| P-12 | UI 定稿后到试运行/上线的正式排期 | 当前只有口头节奏，没有形成正式里程碑承诺。 | 客户预期和项目实际节奏可能脱节。 | 项目经理、技术负责人、客户项目负责人 | 高 |
| P-13 | 培训方案 | 会议里明确了要培训销售和内部支持部门，但未形成落地计划。 | 即使系统上线，用户也可能因不会操作而无法试点。 | 项目经理、实施顾问、客户业务负责人 | 中高 |
| P-14 | 非检外部账号策略 | 当前是基于“固定第三方”在讨论，如果未来合作方变化频繁，现方案可能不够。 | 会影响账号管理、权限安全和运维成本。 | 技术负责人、合规部门、项目经理 | 中 |

## 五、按模块拆解的管理视角结论

### 1. 讲者管理模块

当前共识已经较多，说明讲者管理是本项目里收敛程度最高的模块之一。

已相对明确的内容：

- HCP 绑定要用本人常用手机号
- 讲者升级必须经过四要素验证
- 讲者评级接入第三方
- 结果不一致时有申诉期
- 申诉只能经理发起
- 已认证讲者不能随意改资料
- 有未结算会议时不能变更讲者信息

当前真正的管理重点不是流程本身，而是：

- 去重问题
- 评级时效
- 编码规则
- 角色权限说明

项目经理建议：

- 这一模块适合优先固化为“规则清单”，因为已经接近可以定版。
- 培训计划也可以优先围绕讲者模块先启动，因为其业务价值和前置准备价值较高。

### 2. 会议申请模块

会议申请模块的主流程已经较清楚，但和预算、财务、市场部的耦合度很高，因此其真正的不确定性仍然主要来自跨部门规则。

已相对明确的内容：

- 会议类型按客户 1.0 口径收敛
- 预算前台先走人均费用上限
- 成本中心/项目/费用科目等字段需动态读取
- 费用变化触发重走流程
- 含市场部费用需增加市场审批

当前真正卡点：

- 财务在申请阶段要不要介入
- 销售和财务各自要填写到什么程度
- 预算字段与审批节点联动逻辑

项目经理建议：

- 这一模块不要继续单独开产品会内耗，应该由财务负责人直接参与一次定口会议。

### 3. 会议执行模块

会议执行模块的页面功能争议已不算太大，但合规证据口径仍有几个点要收口。

已相对明确的内容：

- 会议资料主上传放在执行阶段
- 线下会有签到表
- 线上会有参会/观看记录
- 讲者端只保留扫码签到

待进一步定口的核心点：

- 线上讲者是否还要额外签到一次
- 纸质签到表是否必须保留
- 材料打印的完整清单

项目经理建议：

- 执行模块的产品设计应与法务/合规形成一轮专门确认，而不应只在业务会上顺带讨论。

### 4. 结算模块

结算模块是当前风险最高、跨部门协调成本最高的模块。

已相对明确的内容：

- 结算按会议维度管理
- 分为劳务确认和报销结算两步
- 报销提交依赖劳务审核通过
- 已完结会议进入历史
- 最终流向子公司财务，且至少两层审核

仍未落地的关键点：

- 各节点谁审
- 实际发生费用谁填
- 页面字段怎么呈现
- 结算审批链和组织调整如何映射

项目经理建议：

- 结算模块应被视为当前项目第一优先级问题，不解决它，开发即使推进也会反复返工。

### 5. 非检模块

非检模块不是范围最大的模块，但它是领导层和合规部门非常敏感的模块，因此它的政治优先级高于功能复杂度。

已相对明确的内容：

- 一期只做基础能力
- 要有独立账号/后台入口
- 非检人员可选会、拿链接、通知发起人

当前隐患：

- 账号策略还没有完全固化
- 权限范围仍需再确认
- 二期边界需要提前写清

项目经理建议：

- 非检要做成“一期保基本可信，二期再扩完整流程”的典型模块，避免一期开口过大。

## 六、当前最关键的六项项目待办

以下事项建议作为最近一轮项目推进的最高优先级待办：

1. 组织一次`财务定口会`
目标：一次性确认预算字段责任、财务审批链、结算节点和实际发生费用录入口径。

2. 输出一份`编号规则清单`
目标：统一会议编号、流程编号、结算单号、讲者/HCP 编号、材料编号。

3. 输出一份`一期范围边界清单`
目标：明确哪些是 1.0 必做，哪些是 2.0 增强，避免后续扩项。

4. 与法务/合规完成`签到与纸质材料口径确认`
目标：明确线上签到、纸质签到表、归档材料的合规边界。

5. 与第三方确认`评级 SLA 与异常处理`
目标：避免讲者入库节奏不可控。

6. 固化`里程碑计划`
目标：形成 UI 定稿、开发、联调、培训、试运行、上线的正式时间表。

## 七、项目主要风险清单

### R-01 审批流风险

财务和业务审批链如果继续在讨论中变动，会导致开发和 UI 都反复返工。

### R-02 合规口径风险

签到、纸质材料、电子签、非检边界若无正式法务/合规口径，上线后仍可能被推翻。

### R-03 范围膨胀风险

客户参与部门多，若没有正式的一期边界，项目容易持续被追加内容。

### R-04 第三方依赖风险

讲者四要素、评级、电子签都依赖第三方，一旦 SLA 或规则不稳，会直接影响核心流程。

### R-05 验收风险

如果合同和验收条款未与当前方案保持一致，后续极易出现“做了但不算过”的情况。

### R-06 培训与试运行风险

即使系统功能基本完成，如果培训、试点准备和讲者前置数据准备不到位，试运行也会失真。

---

## 八、建议下次会议固定输出格式

建议从下一次开始，每次会议纪要都固定输出以下五类内容：

- `本次拍板事项`
- `本次未拍板事项`
- `新增变更事项`
- `责任人与完成时间`
- `对项目里程碑的影响`

这样可以避免后续再次出现“已经讨论了很多，但难以快速看出哪些真正定了、哪些还没定”的问题。

## 九、结论

从 17 次会议整体来看，康弘会议管理系统项目已经完成了从“发散式需求沟通”向“规则收口与交付准备”阶段的转变。

项目目前最大的问题，不再是“不知道要做什么”，而是：

- 哪些规则已经足够稳定，可以直接开发
- 哪些跨部门口径必须尽快拍板
- 哪些内容必须明确压到二期

如果项目组接下来能够把`财务流程`、`合规口径`、`编号规则`、`验收边界`这四组问题尽快定死，那么项目就可以比较顺畅地进入开发、联调和试运行。

如果这四类问题继续悬而不决，那么后续即使表面上在推进开发，实质上也仍会反复返工。
